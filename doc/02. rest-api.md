# REST API

The desk listens on the address and port from Settings (`0.0.0.0:7443` by default), plain HTTP,
JSON in and out. A release job uses it in this order: open a request with a manifest, upload each
file, poll the request until it ends, fetch the signed files. Everything about a request is
decided here; the job only asks.

Who may call is not settled: the GitHub authentication scheme is still to be decided. Until it
is, every caller is "unverified", which lets a person approve the request after looking at it and
rules out automatic signing.

`scripts/Request-Signature.ps1` is the reference caller, and `scripts/Test-SigningDesk.ps1` the
health check a job runs first.

## Routes

| Route | Who | What |
|---|---|---|
| `GET /health` | anyone | `status`, `version`, `listening_since`, `pending` |
| `POST /requests` | job | Opens a request from the manifest. `201` with the request when accepted, `403` with the request when the checks refuse it, `400` with `error` when the manifest is malformed (nothing is listed). |
| `GET /requests/{id}` | job | The request and its state. |
| `PUT /requests/{id}/files/{name}` | job | One unsigned file, whole, as the body. Checked against the manifest's size and SHA-256 on arrival; a mismatch refuses the whole request (`400` with the request). `409` when the request takes no more files or the file was already received. |
| `GET /requests/{id}/signed/{name}` | job | The signed copy, once the request is `signed`; `404` before. |
| `DELETE /requests/{id}` | job | The job gave up: a request still open becomes `expired`. `409` while it is being signed; harmless once it has ended. |

## The manifest

```json
{
  "repository": "sigmastone-io/neurotrader",
  "ref": "refs/tags/v0.1.0-beta.1",
  "commit": "3b9d1e4f2c07a1b2c3d4e5f60718293a4b5c6d7e",
  "workflow": "rust.yml",
  "job": "package",
  "run_id": 1287,
  "run_url": "https://github.com/sigmastone-io/neurotrader/actions/runs/1287",
  "actor": "sorou",
  "files": [
    { "name": "neurotrader-0.1.0-beta.1-x64.msi", "size": 50528256, "sha256": "9f3c…a71e" }
  ]
}
```

`repository` (owner/name), `ref` and at least one file are required. A file name is a plain
name: letters, digits, `.`, `_`, `-`, `+` and spaces, no path, not starting with a dot. Everything
else is shown to the person and recorded; it is not checked.

### States

```
received -> pending -> signing -> signed
         |          |          -> failed
         |          -> rejected   (the person said no; reason is theirs)
         |          -> expired    (the job gave up, or no approval within 60 minutes)
         -> refused               (a check failed; reason is the check's)
```

`received` lasts until every file in the manifest has arrived and matched. A request that is
refused at `POST` never takes files. File states are `expected`, `received`, `signing`, `signed`,
`failed`.

Signing is `signtool sign /sha1 <thumbprint> /fd sha256 /tr <timestamp> /td sha256` on a copy of
each file, then a check that the copy now carries that certificate's signature, then
`signtool verify /pa` unless the certificate is self-signed. One file at a time, one request at a
time; the first failure fails the request and the files after it are not signed. While a request
is `signing`, `reason` carries what signtool is doing. `approved_by` is the signer's Windows user
name or `automatic`.

Every end state is appended to the signature log, one line per file: time, request, repository,
ref, commit, file, SHA-256, outcome, by (`signer`, `automatic`, `checks`, `nobody`) and reason.

### Checks

Each outcome is `passed`, `failed`, `unverified` or `pending`. Any `failed` refuses the request.
`unverified` (the identity check, until the GitHub scheme exists) leaves the request to a person
and blocks automatic signing. `pending` is the files check while uploads are in flight.

## Limits

- A file is sent in one `PUT` and held in memory until it is hashed and written; release
  artifacts of a few hundred megabytes are fine, multi-gigabyte ones are not what this is for.
- The work directory holds a request's files while it is open; they are deleted when the request
  ends in anything but `signed`, and with the request itself a day later. Requests do not survive
  a restart of the desk; the signature log does.
- No TLS. The desk is meant for the LAN, and the job verifies what comes back.
